# CTO015 independent public-beta readiness audit

**18 November 2026 (Africa/Lagos).** Audit branch `audit/cto015-public-beta-readiness`, based on remote `main` `fde8570aec78c8981dd02e21c6c6fc351e7769c4`. This is an audit of that commit and the observed `https://signalpulse-nine.vercel.app/` response, not a sign-off on Antigravity's in-progress CTO014 branch. No production setting or user record was changed.

## Release decision

**NO-GO for the present production build as a public beta.** The live guidance still tells consumers to wait for a fixed 30-day escalation window and presents a 90-day NCC dispute limit while citing the 2007 code. The [current NCC complaint procedure](https://consumer.ncc.gov.ng/consumer-complaints/procedure-to-file-a-complaint/) says complain to the provider first, then contact the NCC if unsatisfactorily resolved; it does not state either fixed period. NCC's [2024 Consumer Code highlights](https://consumer.ncc.gov.ng/articles/104-highlights-of-the-ncc-consumer-code-of-practice-regulations-2024) place 96 hours on responses to *service-information inquiries*, not general fault repair. Remove the unsupported deadlines and outdated attribution before inviting public reliance. Recheck CTO014's changed copy rather than patching its active UI branch here.

Local-first reporting can be the beta scope after the gates below pass. Keep cloud backup, attachments, live measurement and public aggregates disabled. The CTO012 credential incident and authenticated cloud isolation remain open; they block cloud release, not a demonstrated local-only data leak. Vercel production is already anonymously accessible (HTTP 200), so launch wording and privacy requirements matter now.

## Vercel and production observations

- Anonymous requests to `/`, `/check`, `/incidents`, `/evidence`, `/guidance`, `/intelligence` returned HTTP 200 on 18 November; this proves the current production alias is publicly accessible. It does **not** prove preview protection is enabled or disabled.
- `GET /api/v1/session` returned `signed_out`, null owner and `synthetic-csrf-token`; the current source emits that token in synthetic mode. This is strong evidence the observed deployment is synthetic-only. No real report was submitted. `GET /api/v1/incidents/sync` returned 405, as expected for its POST-only route.
- The Vercel connector can see only another team; the SignalPulse project under `bode-billions` returned 403. Therefore project environment-variable targets, deployment-protection settings, production deployment SHA and secret configuration are **unverified**. GitHub reports a successful Vercel status for main `fde8570`, but that does not prove the production alias points to that SHA. An owner with Vercel scope access must inspect those settings and record the alias deployment ID/SHA.
- The observed site has no CSP; static HTML has public `max-age=0, must-revalidate`, and session JSON has `no-store, private`. No personalized HTML was observed. The code's Supabase client is gated on `cloud_preview`, `NEXT_PUBLIC_ENABLE_CLOUD_BACKUP=true`, URL and publishable key. `CloudBackupCard` also hard-disables enrollment in this baseline. Do not infer the unseen Vercel env values from source defaults alone.
